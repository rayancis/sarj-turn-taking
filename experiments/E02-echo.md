| | |
|---|---|
| Base | P3 candidate (`claude/phase3-research` @ b32cfc2), merged into `claude/keen-shannon-qago5y` |
| Change | `echo_canceller.py` + `AEC = True` in `my_system.py` (STOP path only; TAKE_TURN untouched) |
| Status | **candidate for independent review (Codex); not self-approved; no real-time run yet** |
| New dependency | `livekit==1.3.0` (WebRTC AEC3; Apache-2.0 / BSD-3-Clause; local CPU, no network) — declare in WRITEUP.md |

## Why
Independent acoustic stress sets (`tools/augment_dev.py`, generated by an agent that never saw the detector) showed
P3 collapsing on speakerphone echo: Core 5.0, 49 false stops, 2 misses. Echo is in the kit spec
(SCRIPTS.md: `speakerphone`, echo -15..-25 dB, 150-250 ms). P3's own pilot judged an echo gate "neutral" (D1)
because dev holds a single echo call: the absence of evidence came from the data, not the idea.

## What was tried (offline replay, `tools/replay.py`; diagnostic, not official)
1. Hand-written frequency-domain NLMS canceller: safe but slow (≈3 dB echo reduction during the first agent
   utterance, ≈10 s to converge). Speakerphone 5.0 → 17.2 but a new miss under reverb/tv. Not kept as canceller.
2. WebRTC AEC3 always on: ≈20 dB echo reduction from the first second and big dev gains (orig 73.4 → 84.5,
   tv 16.5 → 63.9), **but** its residual-echo suppressor attenuated real interruptions by 4-16 dB on calls with no
   echo at all: human-voice xdev 95.8 → 59.6 with 6 new misses. Most of the "gain" was half-duplex muting.
   **Rejected.**
3. **Kept:** AEC3 output used only while a linear echo-path detector (the NLMS filter from 1, which cannot learn
   an uncorrelated caller) reports ≥ 6 dB of explained caller energy; released after 3 s below 3 dB (so a caller
   talking over the echo does not switch it off mid-sentence; caught by `tests/test_echo.py`). Divergence guard.

Detector check: on every non-echo call in dev, xdev and 8 tv calls it never reached 6 dB (max < 2 dB); it fired on
all calls labelled as echo (dev NV-D03, xdev GI-D59, NV-D53) and on 21/25 speakerphone stress calls
(median 2.4 s after call start).

## Result (offline replay, P3 → P3+gated AEC)
| Set | Core | misses | false stops |
|---|---|---|---|
| dev original | 73.4 → 73.4 | 0 → 0 | 10 → 10 |
| xdev (human voices) | 95.8 → 95.8 | 0 → 0 | 3 → 3 |
| aug/dev speakerphone | 5.0 → 9.1 | 2 → 2 (GI-D03 newly missed, GI-D01 recovered) | 49 → 37 |
| aug/dev speaker + AC hum | 8.0 → 8.0 | 6 → 4 | 53 → 42 |
| other 13 aug/dev conditions | equal or +1.4..+2.4 | no new miss | equal or -1 |

Holdout sets (`data/aug/holdout`, `data/extra/holdout`) were **not** run.
CPU: on_frame mean 229 → 849 µs (AEC3 + detector + VAD), well inside 20 ms.

## Remaining error (measured)
All 29 analysed speakerphone false stops happen while the gate is still off: mostly the first agent utterance
(500-2000 ms into the call) and 4 calls where the path is never detected (echo under street/phone noise). With the
gate on there were 0 false stops. The fix therefore needs faster echo detection at call start, not a better canceller.
A cue based on AEC3's own attenuation does not separate echo from no-echo (noise is also attenuated); the caller
level rising with the agent's onset separates better but coincides with babble/TV onsets — not adopted.

## Limits
Offline replay only; real-time speed-1.0 run pending. Echo in the stress sets is digital and linear; real phones add
nonlinear echo, which AEC3 handles better than the detector. Stress sets reuse the 24 dev scripts.
