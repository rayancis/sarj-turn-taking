How decisions reach this page
  1. The page plays the call's two channels (agent and caller) from one audio clock and regularly reports its playhead to the server.
  2. The server runs both detectors, each in its own session, on the same frames. For each 20 ms frame it does what the kit's harness and server do: the same control messages (scenario_start, agent_utterance_start/end) in the same order, then the 1,280-byte stereo frame, into MySystem.on_frame of that detector, imported unchanged and checked against its file hash. On the hosted site the server may run up to 0.8 s ahead of what you hear, so network delay cannot make decisions late; each decision only uses audio up to its own frame.
  3. Each decision is validated with the kit's protocol check, stamped with its frame time, and sent back; when playback reaches that time the page marks it, and the selected detector's STOP silences the agent until the end of that utterance.
  4. Labels are read only by the official scorer, after the decisions exist. Nothing here is pre-scripted.
