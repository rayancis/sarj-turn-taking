How decisions reach this page
  1. The page plays the call's two channels from one audio clock and regularly reports its playhead to the server that runs the detector.
  2. For each 20 ms frame the playhead reaches, the server does what the kit's harness and server do: the same control messages (scenario_start, agent_utterance_start/end) in the same order, then the 1,280-byte stereo frame, into MySystem.on_frame of the selected version, imported unchanged. On the hosted site the server runs up to 0.8 s ahead of what you hear, so network delay cannot make decisions late; each decision only uses audio up to its own frame.
  3. Any decision is validated with the kit's protocol check, stamped with its frame time, and sent back; when playback reaches that frame time the page mutes the agent until the end of that utterance. Pause stops the clock and the feed together; Reset and scenario/model changes start a fresh detector.
  4. Labels are read only by the official scorer, after the decisions exist. Nothing here is pre-scripted.
